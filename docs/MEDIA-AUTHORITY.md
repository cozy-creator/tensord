# Media transport authority and viewer admission

An output capability's expiry and the signer's current admission apply for the entire
transport, not only its first message. One StreamAuthority guard detaches an HTTP/gRPC
reader on expiry/revocation and releases its queued output files. It carries no Control
operation and cannot cancel accepted work. HTTP checks again after opening its snapshot
before sending private metadata; body authority is checked before each polled chunk.

Cozy/1 checks authority before pumping/transmitting, so a busy output cannot starve a key
revocation. Its quiet-session wait also includes the explicit capability expiry. On loss,
it drops pending application frames and output tasks and sends the terminal bye. Already
transmitted network buffers cannot be recalled; no further output is generated by that
session after authority ends.

Only unauthenticated handshakes consume capacity limits. Authenticated viewers have no
viewer cap or per-key eviction. Each session continues to bound its own output buffering
and concurrent read requests. The design target remains one or two viewers without a
broadcast/fanout service.

CPU checks cover buffered/quiet guard revocation and expiry, an actual TLS/HTTP body under
backpressure, and authenticated admission past the old viewer caps. Actual cozy/1 browser
expiry/reconnect and ordinary local/rental run play remain required consumer gates. The
checks do not qualify inference or GPU benchmark speed.
